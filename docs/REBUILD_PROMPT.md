## 1. 目标与边界

这是读取本地股票日线并执行明确规则的筛选工具。当前只交付 Windows GUI 与 CLI，共用分析核心。

当前仅实现通达信本地数据源。标准 CSV 行情、AKShare、Tushare、BaoStock 是以后可扩展的数据源；Web、Android、iOS、微信小程序只保留规划与独立发布目录，不能假装已有可执行客户端。

不实现实时行情、下单、回测、精确涨停判断或自动交易。只有下述三种策略，不添加数字价格形态、跌幅策略或独立涨停策略。所有结果都只是筛选记录。

## 3. 通达信数据读取

支持直接读取 ZIP 和解压目录，识别任意外层目录下的 sh/lday、sz/lday、bj/lday；ZIP 路径分隔符兼容斜线与反斜线。无需安装通达信客户端，不要求先解压，不修改原行情文件。

文件名匹配 `(sh|sz|bj)六位数字.day`，大小写兼容，股票范围：

- 上海：6 开头，包括科创板。
- 深圳：00 或 30 开头，包括创业板。
- 北京：43、83、87、92 开头，兼容历史代码。
- 排除不符合范围的指数、基金和可转债文件；这不是完整的实时交易所证券注册服务。

每条 .day 记录为 32 字节、小端结构 `<IIIIIfII`：日期 YYYYMMDD、开盘价、最高价、最低价、收盘价、浮点成交额、成交量、保留字段。价格使用整数分，成交量股、成交额元。转换展示时才除以100，不先转浮点价格参与阈值判断。

验证记录长度、真实日历日期、日期严格递增、OHLC 范围一致性、成交额有限且非负。空文件单独计数；重复股票文件在初始化时报错，不能任意选一份。单只股票损坏、ZIP 成员 CRC 或解压错误要隔离并继续扫描其余股票；打不开整个数据源或没有支持文件则报错。

读取接口提供 `securities()`、`read_bars(security, limit)`、`close()`，返回稳定排序证券及按时间升序的尾部日线。只解析策略所需尾部，ZIP 尾部读取仍可能解压前部，不宣称 ZIP 随机访问零成本。确保取消、异常和完成后都关闭文件。

## 4. 日期规则和上市状态

界面原文必须为：“留空使用行情数据中的最新交易日”（可以在前面附 YYYY-MM-DD）。英文含义一致。

- 留空：取行情数据支持股票中能够成功读取的末条日期最大值作为统一目标日期；不能各股票使用各自不同日期作为结果日期。
- 指定 YYYY-MM-DD：只有文件最后一条记录恰为该日的股票参与策略；文件末条日期更早或更晚都排除。这是末条日期过滤，不是从后续行情截断进行历史回放。
- 没有该日末条数据的股票计入日期不符，不按零价格处理。
- 行情记录符合日期和策略条件就统一处理，不按证券表是否存在、名称是否缺失或上市状态排除。
- 不实现“排除已退市”复选框、CLI 参数、扫描排除逻辑或结果状态筛选；GUI 不显示上市状态列。证券表和导出保留 status 信息仅供查阅。
- 摘牌、停牌和缺失数据不可互相推断。

## 5. 策略一：区间涨幅 gain

参数默认比较周期 N=20、阈值=10（百分数），可修改。N 为正整数，阈值为有限非负十进制数，允许超过100。

```text
base = 倒数第 N+1 条记录的收盘价
latest = 最后一条记录收盘价
gain = (latest - base) / base
命中：gain × 100 ≥ 用户阈值
```

固定使用大于等于，不提供比较符号选择。每只股票最多一条最新结果。N=20 需至少21条记录，N=1比较相邻两条；周期按该股票交易记录计数，不是自然日，不补停牌日。

以整数分差值和 Decimal 阈值交叉相乘比较，不能先把显示百分比四舍五入后筛选。基准或最新收盘价不大于0、历史不足时跳过并计数。恰好10%必须命中，略低于10%即使显示舍入为10%也不得命中。

结果包含基准日期、基准收盘价、最新日期、最新收盘价、gain_ratio 和 gain_pct。gain_ratio=0.12 表示12%，gain_pct=12。

帮助中说明：希望粗略筛选单日接近10%涨停的股票时，可设 N=1、阈值9.9%。这只是涨幅条件；不同板块限制、取整和除权除息会影响结果，不是精确涨停判定。

## 6. 策略二：双均线金叉 ma-cross

使用包含对应当日的收盘价简单算术平均 SMA。默认短周期 F=5、长周期 S=20，满足 1≤F<S。只判断最新一条是否新发生交叉：

```text
上一条：MA(F) ≤ MA(S)
最新条：MA(F) > MA(S)
```

短线已经连续多日高于长线不能重复命中；上一条相等、最新上穿可以命中。以整数和交叉相乘比较，避免均线展示取整改变边界。

附加趋势过滤默认开启，可取消；趋势周期 T 默认120，为正整数。开启时要求最新收盘价严格高于当前 MA(T)，相等不命中。不要求 MA120 自身上升，不增加成交量条件。

需要 `max(S+1, 开启趋势时的T)` 条记录：默认开启120条、关闭21条。历史不足不缩短窗口；参与计算的收盘价有任何非正数则跳过并计数。

结果包含最新与上一条的短、长均线、上一条日期及趋势均线。趋势关闭时趋势均线为空，不能写成0。

金叉另有可选 volume_filter，默认False。启用后要求最新成交量≥此前M条均量×volume_multiple，默认M=5、倍数1.5，窗口排除最新记录，使用整数和Decimal交叉相乘判断。均量为零、负成交量等跳过并计数。放量确认与原MA120趋势条件独立，两项都启用时必须同时满足；不新增均线方向、价格位置或突破高点要求。

界面提供独立复选框和均量窗口、倍数输入；未勾选或扫描时相关输入禁用。金叉与放量突破分别保留参数，语言和策略切换不丢失。关闭放量不计算/展示成交量指标，导出保留开关且未计算字段为null/空，不能写成0；启用时展示成交量、均量和倍数，摘要与导出记录窗口、阈值、起止日期。金叉所需历史=max(长均线+1, 启用趋势周期, 启用均量窗口+1)，额外均量历史不扩大价格有效性检查范围。

## 6.1 策略三：放量突破 breakout

默认价格窗口N=20、均量窗口M=5、成交量倍数1.5，N/M为正整数，倍数为正有限Decimal。最新收盘价严格高于此前N条盘中最高价，同时最新成交量大于等于此前M条平均成交量乘倍数；两个窗口均排除最新记录，至少max(N,M)+1条日线。

原始整数和Decimal交叉相乘判断，不使用展示舍入值。历史不足、无效价格、负成交量或历史均量为零跳过并计数；不要求阳线、首次突破、MA120或最低成交额。每只股票只输出最新一条，可连续刷新高点后在不同日运行时再次命中。

GUI动态显示三个参数，结果含前期最高价、突破幅度、当日成交量、历史平均成交量、成交量倍数。突破幅度=(收盘价/前期最高价-1)×100%，不是当日涨幅；成交量倍数不是盘中量比。GUI成交量用万股，导出原始股数。

导出字段：prior_high、prior_high_date、breakout_pct、volume、average_volume、volume_ratio、price_window_start/end、volume_window_start/end。同价高点日期取最近一次。汇总包含N/M/倍数、窗口排除当天及无效成交量统计，空导出也保留相同表头。按突破幅度降序、市场代码稳定排序。CLI用--breakout-period、--volume-period、--volume-multiple。

帮助统一为“基本使用”和“策略说明”两章，三个策略各自一个小节，简短说明条件、默认值、输出含义和边界，中英文一致，不堆叠工程术语。

## 7. 复权说明

当前 .day 不带可靠复权因子或权益事件，只按原始不复权价格分析，不臆测复权。结果摘要简明说明“当前数据未提供复权因子，按不复权价格分析，分红送转可能影响涨幅和均线”。导出 `price_adjustment=unadjusted`。

帮助解释：不复权收盘价变化不一定等于行情软件公布的除权除息日涨跌幅。未来接其他数据源时明确复权方式、精度和单位；当前不提供无依据的复权开关。

## 10. 分析结果与导出

分析默认只在内存保存，不自动创建结果文件或输出目录。GUI 用户明确选择“导出筛选结果”或“导出全部结果”并选择目录后才写文件；取消选择不创建目录。CLI 仅在显式提供 `--output-dir` 时导出，默认打印摘要。

每次导出到 `淘金人股票分析_时间戳_唯一后缀` 子目录，不覆盖以往结果。导出筛选包含全部命中过滤条件的行；导出全部忽略过滤。关闭程序丢弃未导出内存结果。

生成三份文件：

- matches.csv：UTF-8 BOM、固定表头，六位 code 字符串。
- matches.json：相同记录的数组。
- summary.json：软件版本、生成时间、数据源与路径、价格/单位、实际目标日期、策略参数、要求日线长度、证券总量/读取数/命中数、空文件、历史不足、无效收盘价、日期不符、读错误及明细、末条日期分布、缺失名称数量。

公共字段：market, code, name, board, status, date, close, price_adjustment。涨幅字段：base_date, base_close, gain_ratio, gain_pct。金叉字段：previous_date, fast_ma, slow_ma, previous_fast_ma, previous_slow_ma, trend_ma。价格按元展示，均线可保留6位小数；比较逻辑不使用展示精度。

汇总记录 export_scope（all/filtered）、export_record_count，筛选导出时附 result_filters（market/board/query）。原始分析统计不可替换成筛选后统计，不修改原始内存结果。没有命中也允许导出有表头的空 CSV 和空数组。

## 11. 证券信息表与更新工具

resources/security_names.csv 恰好五列：`market,code,name,status,name_checked_at`。code 为六位文本；status 仅 listed、delisted、unknown；name_checked_at 为 YYYY-MM-DD 或空，表示名称核对日期，不是行情日期。兼容三列旧名称 CSV 时缺失状态视为 unknown。拒绝非法代码、市场、状态、日期或重复市场代码。缺少证券名称不影响策略，名称留空；缺少证券状态导出 unknown。

EXE 和 pyz 优先读取其旁边外置 security_names.csv，缺失才用内置表；源码使用 resources。每次分析重新读取，更新表不要求重新打包或重启 GUI。

独立脚本 scripts/update_security_names.py 更新表，不能把网络名录更新隐式加入分析任务：

- 获取上交所、深交所公开上市及终止上市资料；北交所名称可用巨潮 bj_stock.json 补充，但名称存在不代表仍上市。
- 允许导入已核实北交所名录 CSV（code,name,listing_date）和带官方来源的摘牌覆盖表。
- 未核实状态设 unknown；不能因 ST、行情过旧、名录缺失或名称存在而推断状态。
- 按生效日期处理未来摘牌、重新上市和旧资料覆盖，保留来源证据。
- 下载缓存与更新前备份放工作区 output/security_metadata/日期，支持 --offline、--cache-dir、--checked-at、--bse-listed。
- 校验下载结构和完整性再替换五列表；额外的来源、上市/摘牌生效日期、覆盖数量和 SHA-256 放独立 security_metadata.json，不能向五列 CSV 任意扩列。
- 同步现有 dist/windows、dist/cli 外置证券表与元数据。来源暂时不可访问时清楚报错或使用明确缓存，不伪造已更新。

扫描仅使用本地表中的名称和参考状态进行展示/导出，不以状态决定选股范围。

## 12. CLI、构建和版本

提供源码 `python repo/stockstudy.py`、可选安装命令 stockstudy、`python dist/cli/淘金人股票分析.pyz`。

CLI 子命令 sources 和 scan；sources 只将 tdx 标为已实现，其余标为 planned。

scan 参数包含 `--workspace`、`--source tdx`、`--data`、`--strategy gain|ma-cross|breakout`、`--period`、`--gain-threshold`、`--fast-period`、`--slow-period`、`--trend-period`、`--no-trend-filter`、`--volume-filter`、`--breakout-period`、`--volume-period`、`--volume-multiple`、`--as-of`、`--names`、`--output-dir`、`--quiet`。不添加退市排除、比较符号或独立涨停参数。

退出码：0完成，1参数/整个输入/输出等致命错误，2部分股票读错误。日期正常排除不算读失败。命令帮助、--version、-version、-V显示版本。

scripts/build.py 支持 --target cli/windows/all、--output-root。CLI 使用 zipapp；Windows 在 Windows 系统用 PyInstaller onefile/windowed，打包图标和证券表，目标机器无需另装 Python。发布路径和文件名不带版本号，名称固定淘金人股票分析；每个平台附说明、证券表、来源元数据和 SHA256SUMS。版本统一维护，窗口标题、关于、CLI、汇总和 pyproject一致。

README 保持简洁，详细手册、架构、重建 Prompt 放 docs。独立 CHANGELOG.md 从0.9.3基线开始，之后每次发布记录版本、日期和可见变化，不在 README 写更新历史。

## 13. 验收与交付

用 unittest 和小型确定性合成数据测试，不依赖网络或用户大 ZIP 才能运行测试。至少覆盖：

1. .day 单位、32字节结构、非法字段/日期、空文件、损坏 ZIP、重复证券、ZIP/目录一致性与沪深北识别。
2. 区间涨幅阈值相等命中、略低不命中、周期+1、只取最新一条、历史不足、非正收盘价。
3. 均线从相等上穿、持续多头不重复、趋势过滤相等排除、关闭趋势、周期长度、无效参数和窗口价格。
4. 留空统一取行情最新日；显式日期恰好匹配；日期更早/更晚排除；日期排除不产生CLI读错误退出码。
5. listed/delisted/unknown 在相同日、相同策略条件下均被处理，导出保留状态；缺少名称不阻止选股。
6. 名录结构、生效日期、外置表优先、更新工具离线快照与来源校验。
7. 市场/板块/搜索交集、联动重置、大小写及前导零、超过2000条结果的完整筛选导出、空导出。
8. GUI 参数校验、动态策略、后台完成/取消/错误、语言切换保留参数与结果、没有退市选项。
9. 默认分析不创建输出，取消导出不写文件，多次导出不覆盖，导出汇总保留原始统计。
10. CLI帮助和版本、退出码、pyz启动；在 Windows 实际启动发布 EXE 验证不会一闪而过且有 GUI，帮助和中英文可用。

不要用通过写死真实数据命中数量来代替规则测试。现有项目基线有64项测试，但重建时以行为覆盖为准，不要求凑同样数量。有实际行情时另做冒烟对比，说明样本与限制。提交前检查 Git 中不含数据、缓存或凭据。最终报告实现内容、测试结果、实际发布文件位置和仍未实现的平台；用户明确要求同步 GitHub 时才对其指定仓库推送。
